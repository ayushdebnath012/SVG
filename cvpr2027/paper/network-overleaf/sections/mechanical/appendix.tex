\section{Experience-guided graph search protocol}
\label{sec:pipeline-protocol}
This section specifies the run behind Figure~\ref{fig:pipeline} and Table~\ref{tab:pipeline}, on the \pipeN{} BenchCAD held-out tasks. Every new call uses \texttt{gpt-6-astra} at low reasoning effort with a 2,500-token completion cap (2,000 for semantic judgement). The initial node of each task is the saved medium-effort answer of Section~\ref{sec:pipeline}. A hard budget at list price (\$10 and \$50 per million input and output tokens) refuses any call whose worst-case cost would exceed its cap: \$5 for hypotheses and search, and \$4 more for retrieval and semantics. Responses are saved and never re-billed. The calls cost \$\pipeBranchCost{} for hypotheses (\pipeBranchCalls{} calls), \$\pipeMctsCost{} for search (\pipeMctsCalls), \$\pipeRagCost{} for retrieval (\pipeRagCalls) and \$\pipeSemanticCost{} for semantics (\pipeSemanticCalls), \$\pipeCost{} in total.

\paragraph{Experience retrieval.}
The memory holds the 492 retained BenchCAD training edits and is never updated during evaluation. Each task and memory item is represented by lowercase word counts of its instruction and component name. The two nearest items by cosine similarity are shown as worked examples, each with its instruction, the changed original lines with zero-based indices and its correct patch, followed by the task input under the system prompt of the frontier comparison.

\paragraph{Hypotheses.}
One call per task returns three alternative edits under the following system prompt:
\begin{lstlisting}
You edit mechanical CAD programs. Propose exactly 3 alternative edits for the instruction. Where the instruction is ambiguous (which feature, edge set, reference dimension or construction is meant), make each alternative follow a different reading; if it is unambiguous, vary the implementation. Return only JSON {"candidates":[{"interpretation":"one sentence","edits":[{"start":0,"delete":0,"insert":["replacement line"]}]}, ...]}. Indices are zero-based lines of the ORIGINAL input; operations must be ordered, nonoverlapping and in bounds. Preserve unrelated features. Return no other text.
\end{lstlisting}

\paragraph{Verifier stages.}
\emph{Geometry} parses the answer, applies the patch under the edit contract and executes the program in an isolated CadQuery worker; the result must be a valid solid whose volume IoU with the source is below $0.99999$. \emph{Constraints} extract numbers from the instruction and require each to appear in the inserted lines, accepting ``from $a$ to $b$'', ``by $x$'' and radius/diameter forms. Candidates are also clustered by executed geometry (IoU $\geq0.99999$); cluster size is the consensus. \emph{FEM} meshes the exported STEP solid with gmsh at element size $\max(d/18,0.5)$\,mm for bounding-box diagonal $d$. It solves linear tetrahedral elasticity ($E=210$\,GPa, $\nu=0.3$), with the lowest 5\,\% of the height fixed and a 1\,N axial load on the top 5\,\%. It requires a single anchored component, positive compliance and force, moment and energy balance within $10^{-6}$. A candidate must pass when the source part passes. \emph{Robustness} scales every number in the changed lines by $1\pm0.005$ and reports the fraction of perturbed programs that still give a valid solid with the source candidate's face count. \emph{Semantics} applies only where passing candidates form several geometry clusters. One matplotlib render per cluster shows the source beside the candidate in isometric and top views. Astra returns the best-matching candidate as JSON.

\paragraph{Search.}
A node's value is 0 if geometry fails, and otherwise $0.4+0.2\,[\text{FEM}]+0.2\,[\text{values}]+0.2\,[\text{changed}]$. UCT selects the node maximizing $\bar v+0.7\sqrt{\ln N/n}$, with $N$ the total and $n$ the node's visit count. If the selected node's mean value is below 1, the expansion is a repair. The node's answer is returned with its diagnosis, which names the failed patch application or execution, the FEM failure, missing requested values or an unchanged solid. Otherwise the expansion backtracks: it lists all passing alternatives and requests one meaningfully different edit. The new node is evaluated and its value backed up along the path to the root. Tasks with no passing candidate are searched first, then tasks whose passing candidates disagree on geometry; tasks with unanimous passing candidates are not searched.

\paragraph{Selection.}
Hard gates are geometry, FEM (when the source passes), no contradicted instruction value and a changed solid. Among passing nodes, the Pareto front is taken over semantic vote, consensus, presence of instruction values and robustness. The node with the lexicographically largest objective vector is chosen, and ties keep the original answer. If no node passes, the original answer is kept.

\paragraph{Deterministic repair.}
For the 252 saved Astra answers we also run a monotone repair loop. A diagnosis records the furthest stage reached (parse, apply, execute, valid solid). Candidate fixes either re-indent or de-indent inserted CadQuery lines, or, for CAD-Editor commands, clamp coordinates to the six-bit range, clamp rotation entries to $[-1,1]$, round non-integers, trim surplus curve fields and insert missing terminators. A fix is accepted only if it reaches a later stage, for up to three rounds.

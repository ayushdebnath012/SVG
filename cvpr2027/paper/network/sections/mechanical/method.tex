\section{Astra-guided CAD patch repair}
\label{sec:method}
\subsection{Original-source patch contract}
Given source program $C$ and edit instruction $u$, Astra proposes patch $p$, and an executor builds $\hat C=\mathcal E(C,p)$. Each operation contains a zero-based original line index, deletion count and replacement-line list. Operations must be typed, ordered, nonoverlapping and in bounds. CadQuery syntax or the native command schema is validated after application.

Repair revises the patch. Astra receives a failed candidate and a structured diagnosis, then generates a replacement patch whose indices still refer to $C$. Repairs are never silently concatenated onto an already modified program. The source and all candidate patches remain available in the trace; a verified selection exports executable CAD and a STEP solid.

\subsection{Retrieval and graph exploration}
Experience retrieval supplies prior CAD edits and, in the general implementation, successful repair trajectories. Task decomposition records requested changes and preserved features. Diverse hypotheses produce candidate CAD states. MCTS or best-first scheduling controls expansion, repair and backtracking within a fixed resource budget. Exact-state reuse must preserve model-visible context and edge statistics; similar volume or views alone are insufficient for merging.

Feasible candidates enter a bank. Pareto filtering compares declared objectives, followed by a fixed tie-break. Final robustness checks can return a candidate to search while budget remains. An empty verified bank yields an explicitly unverified fallback, not a certified solution. The recorded benchmark uses the narrower protocol in Section~\ref{sec:pipeline}: its experience memory is frozen, and decomposition and repair-strategy retrieval are not exercised. Implementation capability and measured experiment scope are reported separately.

\subsection{Hierarchical verification}
The hierarchy comprises geometry, constraints, semantics, FEM and robustness. Geometry checks patch application, execution, positive volume and solid validity. Explicit measurable constraints are checked on executed geometry; the recorded benchmark additionally uses numeric-literal heuristics from instructions. Semantic judgement uses Astra and rendered source/candidate views. These are imperfect signals, not access to a target program or proof of reference agreement.

Physical checks require declared units, material, fixture, load and acceptance criteria. The implementation records missing required contracts or inconclusive solves as unknown. The recorded benchmark uses a disclosed synthetic linear-elastic scenario, with its source-conditioned FEM gate specified in Appendix~\ref{sec:pipeline-protocol}. Robustness under selected perturbations is limited to those perturbations; passing does not certify manufacturing tolerance or operating safety.

\subsection{Offline outcome measurement}
Reference solids are reserved for final scoring. For predicted solid $\hat B$ and released or reconstructed target $B^\star$, volume intersection-over-union is
\begin{equation}
J_{\rm vol}=\frac{V(\hat B\cap B^\star)}{V(\hat B)+V(B^\star)-V(\hat B\cap B^\star)}.
\end{equation}
The local strict threshold is $0.99999$. Patch validity, execution success and strict reference agreement are distinct outcomes. References never supply online search rewards or select a patch during inference.
